# ADR-002: Start as a modular monolith

Status: Accepted
Date: 2026-09-21

## Context

QFL is a solo project with requirements that are still unclear and will change as I learn.

## Decision

Build one repository and one application, with clearly separated internal modules (data, research, risk, and so on). No microservices, message queues, or multiple repositories at the start.

## Reason

- Simpler to build, run, test, and debug
- Boundaries can be changed cheaply while I am still learning what they should be
- Distributed systems add failure modes I do not need yet

## Consequences

- Module boundaries must be enforced by discipline, since nothing physically separates them
- Splitting out a component later takes real work, and we accept that
- Split only when a concrete technical reason appears (performance, isolation, independent deployment)
